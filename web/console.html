How this demo works
For anyone reviewing the project. Everything runs on this computer; nothing is sent anywhere.

What this is

A monitoring and auto-remediation toolkit for Windows, driven by one JSON file. Five PowerShell monitors (processes, CPU and memory, disks, network, and documents: a total in a CSV or Excel file, or a file's size) check this machine on their own schedules. When a threshold is crossed they act: a log line, a desktop popup, an email draft, or a remediation script.

How it fits together

  1. 1
    Settings editor → one JSON file

    Every monitor, threshold and action lives in monitoring_settings.json. A health check (doctor.bat) validates it before anything starts.

  2. 2
    Monitors → actions

    Each monitor runs in its own hidden PowerShell process. A problem that lingers is one incident: one popup, at most one email draft per hour, while logging and remediation keep going.

  3. 3
    State files → this consoleYou are here

    Monitors write their state every cycle and the console reads it every 10 seconds. A monitor whose state stops updating is shown as down, so a stuck monitor can't look healthy.

Things to try

  • Open Notepad, then close it. Its row turns green, then red, and the log records both.
  • Click Open Monitoring settings. The Settings Editor (demo) row under Network turns green within 30 seconds.
  • In sample_data/monthly_budget_sample.csv, change the last Groceries amount from 22.00 to 90.00 and save. The budget turns critical.
  • Pause a monitor here, then run doctor.bat. It reports that monitor as not running.
  • Click Stop monitoring in this banner. Every card turns Paused, and Start monitoring brings them all back.
  • Watch Monitor log size under Document: it reads the size of logs/monitor.log, not its contents.
  • Hover or tab to an ⓘ icon to see that item's thresholds and actions.
